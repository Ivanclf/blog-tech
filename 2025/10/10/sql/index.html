SQL基础

这部分主要涉及SQL语法及部分实现上的差别，暂不涉及太底层的内容。还有一些数据库考试用到的概念也会写在这里。

SQL 与 NoSQL 的区别

SQL（关系型） NoSQL（非关系型）
数据存储类型 结构化存储：行、列由 schema 预先定义的二维表 非结构化或半结构化，没有固定 schema。文档：JSON 文档；键值：键值对；宽列：行键 + 动态列族；图：节点和边
例子 Oracle、MySQL、SQL Server、PostgreSQL 文档：MongoDB、CouchDB
键值：Redis、DynamoDB
宽列：Cassandra、HBase
图：Neo4j、Amazon Neptune、Giraph
ACID 属性 完整支持原子性、一致性、隔离性和持久性（ACID） 多数为了可扩展性和性能放弃跨行事务，少数已补齐（如 MongoDB 4.0+ 的多文档事务）
性能 受磁盘 I/O 影响大，通常靠优化查询、索引和表结构提升 受集群规模、网络延迟和访问模式影响更大，靠加节点换吞吐
扩展 以垂直扩容（换更强的机器）为主，也能通过读写分离、分库分表做横向拆分 天然支持水平扩展，靠分片（sharding）把数据摊到多台机器

数据库概念

数据库的数据模型按抽象层次分为概念模型、逻辑模型和物理模型。概念模型按用户视角建模，用于数据库设计，如 E-R 模型；逻辑模型和物理模型按计算机视角建模，用于 DBMS 的实现。

数据模型的组成要素是数据结构、数据操作和完整性约束条件。

数据库采用三层模式结构，从用户到物理存储依次是外模式、模式和内模式。

  • 外模式：用户或应用程序看到的数据逻辑结构。一个数据库可以有多个外模式。
  • 模式：全体数据的全局逻辑结构，即有哪些表、哪些属性、什么类型和约束。一个数据库只有一个模式。
  • 内模式：数据的物理存储结构，定义数据库在存储介质上的存放方式。一个数据库只有一个内模式。

三层之间靠两级映像解耦：外模式/模式映像保证逻辑独立性，改模式时只需改映像，外模式和应用程序不动；模式/内模式映像保证物理独立性，改存储结构时模式不用动。

数据库的完整性是指数据的正确性和相容性：正确性指数据符合现实世界的语义，相容性指同一对象在不同表中出现时彼此吻合。完整性约束分为三类

  • 实体完整性：主码唯一且非空。
  • 参照完整性：外码的取值必须是被参照关系中已存在的主码值，或者为 null。
  • 用户定义完整性：针对具体业务的约束，如年龄必须大于 0。

数据库设计按 需求分析 $\rightarrow$ 概念结构设计 $\rightarrow$ 逻辑结构设计 $\rightarrow$ 物理结构设计 $\rightarrow$ 数据库实施 $\rightarrow$ 数据库运行和维护 依次进行。

嵌入式 SQL 与主语言通信时，涉及三个概念：

  • SQL 通信区（SQLCA）：存放 SQL 语句执行后的状态信息，应用程序从这里取出执行结果。
  • 主变量：SQL 语句中引用的主语言变量，用于在两种语言之间传递数据。
  • 游标：SQL 面向集合，一条语句可能返回多条记录；主语言面向记录，一组变量一次只能放一条。游标用来逐条访问结果集，协调两种处理方式。

数据库范式

范式解决的是冗余问题：让同一份事实只存一处，避免插入、删除、更新时的异常。

第一范式（1NF）

属性的域具有原子性，即每个属性值都是不可再分的最小单元。

比如把”电话”存成 138xxx / 010-xxx 就不满足 1NF；拆成两列，或单开一张电话号码表才对。

1NF 只要求”列不可再分”，不涉及表间关系。

函数依赖

设关系模式 $R$ 的属性全集为 $U$，$\alpha, \beta \subseteq U$。

函数依赖 $\alpha \rightarrow \beta$：任意两个元组只要在 $\alpha$ 上取值相同，在 $\beta$ 上也必然相同，即 $\alpha$ 唯一决定 $\beta$。

按定义是否恒成立，分两类：

类型 条件 说明
平凡函数依赖 $\beta \subseteq \alpha$ 左边已经包含了右边，恒成立，不携带新信息
非平凡函数依赖 $\beta \not\subseteq \alpha$ 真正有约束力的依赖，范式讨论的都是这一类

给定函数依赖集 $F$，由 $F$ 用 Armstrong 公理能推出的全部函数依赖构成 $F$ 的闭包 $F^+$，显然 $F \subseteq F^+$。

完全、部分与传递依赖

概念 定义
完全函数依赖 $X \rightarrow Y$，且 $X$ 的任一真子集 $X’$ 都不能决定 $Y$
部分函数依赖 $X \rightarrow Y$，但存在 $X’ \subset X$ 使 $X’ \rightarrow Y$，即只用一部分属性就能决定 $Y$
传递函数依赖 $X \rightarrow Y$、$Y \rightarrow Z$，且 $Y \not\rightarrow X$、$Z \not\subseteq Y$，则 $X \rightarrow Z$ 是传递依赖

候选键与主属性

  • 候选键：能唯一标识一个元组、且去掉任一属性后就不再唯一的属性集，即最小超键。
  • 主键：从候选键中挑一个用于标识。候选键可以有多个，主键只有一个。
  • 主属性：包含在任一候选键中的属性；其余为非主属性。

第二范式（2NF）

在 1NF 基础上，每个非主属性都完全函数依赖于候选键，不能出现部分依赖。换句话说，不能让”半个主键”就决定某一列。

它只约束非主属性，主属性之间怎么依赖不管。

例如选课表 (学号, 课程号, 成绩, 课程名)，主键是 (学号, 课程号)，但课程名只依赖课程号 → 部分依赖 → 不满足 2NF。应拆成 (学号, 课程号, 成绩) 和 (课程号, 课程名)。

第三范式（3NF）

对 $F^+$ 中每个非平凡依赖 $\alpha \rightarrow \beta$，至少满足一条：

  • $\alpha$ 是 $R$ 的超键；
  • $\beta - \alpha$ 中每个属性都是 $R$ 的主属性。

只看非主属性的话，等价于”非主属性不传递依赖于候选键”。

BC 范式（BCNF）

对 $F^+$ 中每个非平凡依赖 $\alpha \rightarrow \beta$，$\alpha$ 必须是 $R$ 的超键。

它比 3NF 更严：3NF 还允许主属性传递依赖候选键，BCNF 不允许。

$\alpha$ 是 $R$ 的超键，当且仅当 $\alpha \rightarrow R$，即 $\alpha$ 能决定关系模式中的全部属性。

分解的性质

拆表时有两个理想性质：

  • 无损连接：按公共属性 join 回去，不多行也不丢行。
  • 依赖保持：拆分后各表上的函数依赖合起来仍能推出原来的 $F$，校验时不必跨表 join。

3NF 分解总能同时做到无损连接和依赖保持；BCNF 分解只保证无损连接，不保证依赖保持。 这就是工程上常停在 3NF 的原因。

总结

范式 要求 常见说法
1NF 属性原子 列不可再分
2NF 非主属性完全依赖候选键 消除非主属性的部分依赖
3NF 非主属性不传递依赖候选键 消除非主属性的传递依赖
BCNF 非平凡依赖的左边都是超键 主属性也不允许部分 / 传递依赖

日常说的”三范式”就是 1NF、2NF、3NF。

关系代数

关系代数是过程化的查询语言：写出得到结果的操作步骤，SQL 的 select ... from ... where 就是它的变形。

运算分两类：

类别 运算 符号 作用
基本 选择 $\sigma$ 按条件筛行，元数不变
基本 投影 $\pi$ 挑列并去重，元数减少
基本 并 $\cup$ 两个同结构关系的行合到一起
基本 集合差 $-$ 在左边但不在右边中的行
基本 笛卡尔积 $\times$ 两关系的行两两拼接
基本 重命名 $\rho$ 给关系或属性换名，自连接时必用
导出 交 $\cap$ 同时出现在两个关系中的行
导出 连接 $\bowtie$ 笛卡尔积后按条件筛选
导出 除 $\div$ 「对所有」语义，等价于双重 not exists

导出运算都能用基本运算写出来，单列出来只是为了少写几层嵌套。

比如，找出余额最大的账户。思路是「先排除所有不是最大的，再从全集里减掉」：

$$
\Pi_{\text{balance}}(\text{account}) - \Pi_{\text{A1.balance}}\left(\sigma_{\text{A1.balance}<\text{A2.balance}}(\rho_{\text{A1}}(\text{account})\times\rho_{\text{A2}}(\text{account}))\right)
$$

$\rho$ 把同一张表复制成两个别名，$\times$ 造出所有账户对，$\sigma$ 只留下「有人比我大」的那些，投影出它们的余额，最后用集合差从全体余额中减掉。

除运算处理「所有」：$R \div S$ 从 $R$ 中挑出与 $S$ 里每一个元组都配对的元组。典型例子是 R(student, course) 为选课记录、S(course) 为课程表，$R \div S$ 就是选了 S 中全部课程的学生。

数据类型

各库的类型名和上限略有差异，这里以 MySQL 为主，同时标出区别。

字符类型

char(n) varchar(n)
长度 定长，不足右补空格，取值时去掉尾部空格 变长，按实际长度存
占用 恒为 n 实际长度 + 1~2 字节长度前缀
上限 255 字符 见下表
适用 长度固定的短字段，如性别、MD5、邮编 长度不定的字段，如姓名、地址

varchar 的上限各库不同：

数据库 上限
MySQL 单列最长 65535 字节，且所有列共享这个行上限；utf8mb4 下一个字符最多 4 字节，所以大约 16383 字符
PostgreSQL 可以不写长度，实际受单行 8 kB（可调）限制
SQL Server varchar 8000 字节，nvarchar 4000 字符
Oracle varchar2 4000 字节（extended 模式下可到 32767）

二进制与文本

blob text
存什么 二进制字节，不做字符集转换 文本，按字符集存储
典型用途 图片、音视频、序列化对象 长文章、日志
注意 大字段会让行溢出、拖慢查询 只能建前缀索引；早期版本不支持默认值

实际项目里文件一般放 OSS / 对象存储，库里只存 URL，blob 基本用不上。

时间类型

datetime timestamp
占字节 8 4
存什么 字面日期时间，不随时区变化 UTC 时间戳，读取时按当前会话时区转换
范围 1000-01-01 ~ 9999-12-31 1970-01-01 ~ 2038-01-19（2038 问题）
自动更新 需要显式写 on update current_timestamp 可自动初始化、自动更新

跨时区业务用 timestamp 更省心，但注意 2038 上限；只记录”某地某时发生了什么事”的话，datetime 更直观。

NULL

null 表示”值未知或不存在”，'' 是长度为 0 的空串，两者不同。

  • 任何值与 null 比较（=、>、<>）结果都是 null，既不是 true 也不是 false；判断只能用 is null / is not null。
  • where 把 null 条件当作不成立：where age <> 20 会漏掉 age is null 的行。
  • count(*) 统计所有行，count(col) 跳过 null；sum / avg / max / min 都忽略 null，所以 avg 算的是”非空值的平均”，可能和直觉不符。
  • 唯一索引允许多行为 null，null 之间不算重复。

其他

顺丰科技 - 秋招, 一面

  • MySQL 没有独立的布尔类型，boolean 只是 tinyint(1) 的别名，0 为假、非 0 为真。
  • int(11) 里的数字是显示宽度，与取值范围无关，而且必须配合 zerofill 才补零：
    • int(2) 存 12，显示还是 12，超宽就完整显示，不截断；
    • int(11) zerofill 存 12 才显示 00000000012。
    • MySQL 8.0.17 起整数显示宽度已被标记弃用，8.0.19 起 show create table 也不再输出。

查询相关

join

类型 结果
inner join 只保留两张表都匹配上的行
left join 左表全部保留，右表匹配不上的列补 null
right join 反之
full outer join 两边都保留（MySQL 不支持，用 left join union right join 模拟）
cross join 笛卡尔积，等价于不带 on 的 join

on 决定怎么匹配，where 在 join 之后过滤。写外连接时如果把右表的过滤条件放到 where 里，补出来的 null 行会被筛掉，外连接就退化成内连接了——这类条件要写在 on 里。

in 与 exists

in exists
写法 col in (子查询) exists (子查询)
语义 值出现在子查询结果中 子查询是否返回至少一行
与外部查询的关系 子查询通常可独立执行 常写成引用外部列的相关子查询
null 陷阱 not in 一旦碰到子查询结果里有 null，整体变成 unknown，一行都选不出来 不受影响

“in 先跑子查询、exists 逐行跑”是教科书说法；现代优化器会把两者都改写成 semi-join，性能差异往往不大。真正要记的是 not in + null 会静默返回空集，这种场景一律用 not exists。

union / union all / join

方向 是否去重
union 纵向，行数相加 去重，需要排序或哈希，代价高
union all 纵向，行数相加 不去重，最快
join 横向，列拼接 不涉及

union 要求各 select 列数相同、类型兼容，结果列名取第一个 select 的。

集合运算

运算 Oracle MySQL SQL Server / PostgreSQL
交 intersect intersect（8.0.31+） intersect
差 minus except（8.0.31+） except

MySQL 在 8.0.31 之前没有这两个运算符，只能用 join / not exists 模拟。

like

通配符 含义
% 任意个字符，包括 0 个
_ 恰好一个字符

'%abc' 这种以通配符开头的模式用不上索引，必然全表扫描。要匹配通配符本身得转义：MySQL 默认用 \，SQL Server 可以写 [%]，标准写法是 like 'a\%b' escape '\'。

where 与 having

where 在分组前过滤行，having 在分组后过滤组。having 里可以出现聚合函数，where 不行；能在 where 过滤的别拖到 having，越早筛掉数据越省。

with（CTE）

with 定义一个只在本条语句内有效的临时结果集，比多层嵌套子查询好读，也能被重复引用。

MySQL 8.0、PostgreSQL、SQL Server 都支持；树形结构用 with recursive。

> all (...) 比结果中每个值都大
exists (...) 子查询非空为真
unique (...) 子查询结果没有重复行 SQL 标准谓词，MySQL 不支持

数据修改与约束

drop / delete / truncate

delete truncate drop
类型 DML DDL DDL
删什么 满足 where 的行，可以只删一部分 全部行，保留表结构 表结构和数据一起删
能否回滚 事务内可以 不能（隐式提交） 不能
触发 trigger 会 不会 不会
自增 id 不重置 重置为 1 —
速度 慢，逐行删并写日志 快，直接重建数据页 快

delete 不带 where 时结果看着和 truncate 一样，但上表这些差别都在。

约束

可以在 create table 时声明，也可以用 alter table 补加。

约束 作用 注意
not null 该列不能为 null
unique 列或列组合的取值不重复 允许多行为 null
primary key 唯一标识一行，等于 not null + unique 一张表只能有一个
foreign key 引用另一张表的主键 / 唯一键 父行被删时的行为由 on delete cascade / set null / restrict 决定
check 列值满足给定表达式 MySQL 8.0.16 起才真正检查，之前只解析不生效
default 未显式赋值时的默认值 blob / text 早期版本不能设默认值

从理论上看，这些约束对应三类完整性：主键 → 实体完整性，外键 → 参照完整性，其余（check、not null、default 等）→ 用户定义完整性。

事务

  • rollback to savepoint 只撤销保留点之后的语句，事务本身还在，之后仍要 commit 或 rollback。
  • select 也在事务里，受隔离级别影响，只是它没有副作用，回滚改变不了什么。
  • MySQL 中 create、drop、truncate、alter 等 DDL 会隐式提交当前事务，无法回滚。

执行计划 explain

在语句前加 explain 就能看执行计划，不真正执行。

列 含义
id 查询序号。id 大的先执行，id 相同的从上到下执行
select_type 该行的查询类型：simple 简单查询、primary 最外层查询、subquery 子查询里的第一个 select、derived 派生表（from 中的子查询）、union union 中后面的 select、union result union 的结果集
table 这一行访问的表
partitions 命中的分区
type 访问方式，判断效率的核心指标：system > const > eq_ref > ref > range > index > all。到 range 都算可接受；index 是全索引扫描，all 是全表扫描，这两种基本都要优化
possible_keys 可能用到的索引
key 实际使用的索引，null 表示没走索引
key_len 索引上用到的字节数，可用来判断复合索引用到了前几列，不是越短越好
ref 索引列在和哪个值 / 哪一列比较
rows 预估扫描行数，越小越好
filtered 扫描后经条件过滤剩下的行占比
extra 额外信息：using index 覆盖索引、using where 回表后再过滤、using index condition 索引下推、using temporary 用了临时表、using filesort 额外排序、using join buffer 用了 join 缓冲区

看到 using temporary 或 using filesort 基本说明还能优化；看到 using index 说明没回表，是好消息。

lower(s) / upper(s) 转小写 / 大写
replace(s, from, to) 子串替换

注意 substring 的第三个参数是长度，不是结束位置：substring('abcdef', 2, 2) 得到 'bc'。

数值与条件

函数 作用
round(x, d) 四舍五入到 d 位小数
if(cond, a, b) cond 为真返回 a，否则返回 b
case when ... then ... else ... end 多分支判断，是表达式不是函数
nullif(a, b) a = b 时返回 null，否则返回 a
ifnull(a, b) a 为 null 时返回 b，否则返回 a（MySQL 专有）
coalesce(a, b, ...) 返回第一个非 null 的参数，全为 null 则返回 null（标准 SQL）

计数

写法 统计范围
count(*) 所有行，包括所有列都是 null 的行
count(1) 与 count(*) 等价
count(col) 只统计该列非 null 的行

count(*) 和 count(1) 没有实质差别，不用纠结；真正有区别的是 count(col) 会跳过 null。

日期时间

函数 作用
now() / curdate() / curtime() 当前日期时间 / 日期 / 时间
to_days(d) 从公元 0 年 1 月 1 日到 d 的天数
date_add(d, interval n unit) / date_sub(...) 加 / 减 n 个单位，unit 可以是 day、month、hour 等
datediff(d1, d2) 两个日期相差的天数，只看日期部分
timestampdiff(unit, t1, t2) 两个时间点相差多少个 unit，如 timestampdiff(hour, a, b)
date(t) 取出时间中的日期部分
last_day(d) d 所在月的最后一天

窗口函数

窗口函数在保留明细行的同时做排名或聚合，比自连接、相关子查询清爽得多，MySQL 8.0 起支持。

partition by 决定分组（不写就是整表一组），order by 决定组内顺序。不写 order by 时窗口是整个分组；写了之后默认是”从分组第一行到当前行”，这就是 sum(x) over (order by ...) 会得到累计值的原因。

函数 作用
row_number() 组内连续序号，不并列：1, 2, 3
rank() 并列同名次，之后跳号：1, 1, 3
dense_rank() 并列同名次，不跳号：1, 1, 2
ntile(n) 把分组均分成 n 份，返回所在桶号
lag(expr, n) / lead(expr, n) 取前 n 行 / 后 n 行的值，n 默认 1
first_value(expr) 窗口第一行的值
last_value(expr) 窗口最后一行的值；默认窗口到当前行为止，通常要显式写 rows between unbounded preceding and unbounded following
sum / avg / count 等聚合 加上 over (...) 后按窗口聚合，不再折叠行
